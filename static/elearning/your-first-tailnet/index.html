    Lesson 1

    What is a tailnet?

    A tailnet is your own private network. Every device you add can reach the others, wherever they are.

    Your laptop might be in a café, your phone on mobile data and your file server at home. Normally, those three can't reach each other without opening ports or setting up a VPN server. Once they join the same tailnet, they behave as if they were on one network.

    Lesson 2

    How devices find each other

    A central coordination server introduces your devices. After that, they talk to each other directly.

    Tailscale splits the work in two. The control plane is the coordination server: it handles sign-in, shares keys and sends out your access rules. The data plane is your devices: they carry your actual traffic, encrypted with WireGuard.

    or use the ← → arrow keys
    Fig 2The control plane shares keys and rules. The data plane carries your traffic.
    Good to know

    If the coordination server goes offline, devices that are already connected keep working, using the rules they last received.

    Lesson 3

    Direct or relayed?

    Tailscale always tries for a direct connection. When a network won't allow one, it relays your traffic instead, still encrypted.

    Every connection starts out relayed through a DERP server (Designated Encrypted Relay for Packets), so devices can reach each other straight away. Tailscale then tries to upgrade to a direct connection. If a firewall blocks that, it tries a peer relay in your tailnet, if you've set one up. Otherwise it stays on DERP.

    Check which one you have
    
  
    Run tailscale status and look at the line for the other device. direct means direct. relay means DERP, with a short code for the relay's city, like "tor" for Toronto. tailscale ping shows the same thing, one reply at a time.
    
  
    

    



    
  
    Lesson 4 · Hands-on
    
  
    Connect two devices
    
  
    Set up your tailnet and reach one device from the other. Tick each step as you go.
    

  
    
    
    1. Install Tailscale on your first device
    
    
    Download it from tailscale.com/download.
    
    
    
      
      
      
    
    
    
    
  
    

  
    
    
    2. Sign in
    
    
    Sign in with an identity provider you already use, such as Google, Microsoft or GitHub. Your first sign-in creates your tailnet.
    
  
    

  
    
    
    3. Add a second device
    
    
    Install Tailscale on another device, like your phone, and sign in with the same account. Both devices now appear in the admin console.
    
  
    

  
    
    
    4. Check that both devices are there
    
    
    On a computer, open a terminal and run:
    
    
    $ tailscale status
100.101.102.103  laptop  you@  macOS  -
100.88.12.40     phone   you@  iOS    active; direct 203.0.113.7:41641
    
    
    Your addresses and names will be different. Each line is one device, with its Tailscale IP first.
    
  
    

  
    
    
    5. Reach the other device by name
    
    
    Ping your second device by its MagicDNS name:
    
    
    $ tailscale ping phone
pong from phone (100.88.12.40) via DERP(tor) in 41ms
pong from phone (100.88.12.40) via 203.0.113.7:41641 in 9ms
    
    
    Notice the first reply came through a relay and the second came direct. That's the upgrade from Lesson 3, happening live.
    
  
    

  
    Nice work
    You've built a tailnet. Right now, every device in it can reach every other device. The next lesson shows you how to change that.
    
  
    

    



    
  
    Lesson 5
    
  
    Decide who can reach what
    
  
    A new tailnet lets every device reach every other device. Access rules let you narrow that down.
    
  
    You write rules in the tailnet policy file, in the admin console. The recommended kind of rule is a grant. Each grant says who can connect (src), to what (dst), and on which ports (ip). Once you write your own rules, anything you don't grant is blocked.
    

  
    
    
    
    Fig 4One grant opens one path. Anything not granted stays closed.
    
  
    

  
    Here's that grant in the policy file, with the group and tag it uses:
    

    // Who's in the group
"groups": {
  "group:eng": ["ana@example.com", "sam@example.com"]
},
// Who's allowed to apply the tag to a device
"tagOwners": {
  "tag:server": ["autogroup:admin"]
},
// The rule itself
"grants": [
  {
    "src": ["group:eng"],
    "dst": ["tag:server"],
    "ip":  ["tcp:443"]
  }
]
    
  
    Tip
    Use groups for people and tags for servers. When someone joins the team, you add them to the group instead of editing every rule.
    

  
    Practice: would this connect?
    
  
    Use the policy file above. Remember: only group:eng (Ana and Sam) can reach tag:server, and only on tcp:443. Decide whether each connection is allowed.

    Design notes
    
  
    Style guide for this module
    
  
    The design system behind this course: how it looks, how diagrams are drawn, and how it's written.
    
  
    Visual direction matches Tailscale's docs site (tailscale.com/docs), so the course would sit naturally beside it. No Tailscale logos or marks are used.
    

  
    Colour
    
  
    A white page, near-black text and hairline borders instead of shadows, as on the docs site. Blue is the only accent: it marks links and the paths traffic takes in diagrams.
    
  
    
    
    Page#FFFFFF
    
    
    Surface#FAF9F8 · code, panels
    
    
    Hairline#EEEBEA · borders
    
    
    Ink#181717 · 17.9:1
    
    
    Body text#2E2D2D · 13.7:1
    
    
    Muted text#706E6D · 5.1:1
    
    
    Docs blue#3B82F6 · graphics only
    
    
    Link blue#2563EB · 5.2:1
    
  
    
  
    Accessibility decision
    The docs site uses #3B82F6 for links. On white that's 3.7:1, under the 4.5:1 that WCAG AA requires for body text. This module keeps that blue for diagrams, where 3:1 is enough, and uses #2563EB for links.

    Every diagram has a figure number and a one-line caption that states the takeaway, not just what's shown.
    

  
    Voice
    
  
    
    
    Do"Every connection starts out relayed, then tries to go direct."
    
    
    Don't"Tailscale leverages a sophisticated NAT traversal methodology to optimize connectivity."
    
    
    DoOne idea per sentence. Define a term the first time, then use it the same way every time.
    
    
    Don'tStack acronyms, or switch between "tailnet," "network" and "mesh" for the same thing.
    
  
    

  
    Course structure
    
  
    Each lesson follows the same pattern: a title, a one-sentence lede, a short explanation, one interactive diagram or exercise, and a single "Continue" action. Concepts come before the hands-on lesson, so the commands make sense when learners run them.
